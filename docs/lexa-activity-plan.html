Task Activity Timeline + Comments

A unified activity timeline in the task slideover — human comments and system events interleaved, like GitHub's issue timeline. Reverses the v1 "comments-free" cut; driven by the missing context trail and agent visibility. Comments stay in Lexa (no GitHub sync).

01Data model — two append-only tables

SCHEMA.md additions · migration 00XX · rowid ids fix the second-granularity tie-break (UUIDs don't order chronologically).

task_comments soft delete
id           INTEGER PRIMARY KEY AUTOINCREMENT
task_id      TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE
author_id    TEXT REFERENCES users(id) ON DELETE SET NULL  -- NULL: agent/system
author_kind  TEXT NOT NULL DEFAULT 'user'
             CHECK (author_kind IN ('user','agent','system'))
author_label TEXT NOT NULL        -- frozen name at write time
body         TEXT NOT NULL        -- TipTap JSON doc
edited_at    TEXT                 -- set on edit → "edited" marker
deleted_at   TEXT                 -- soft delete → hidden from timeline
created_at   TEXT NOT NULL DEFAULT (datetime('now'))
Index: (task_id, created_at, id) · body ≤ 64KB, non-empty TipTap doc (invariant #11 emptiness check)
task_activity append-only
id            INTEGER PRIMARY KEY AUTOINCREMENT
task_id       TEXT NOT NULL REFERENCES tasks(id) ON DELETE CASCADE
actor_kind    TEXT NOT NULL CHECK (actor_kind IN ('user','agent','system'))
actor_label   TEXT NOT NULL        -- frozen display name
actor_user_id TEXT REFERENCES users(id) ON DELETE SET NULL
                                   -- agent: key owner · user: their id · NULL: unbound/system
type          TEXT NOT NULL        -- enum in shared/types.ts (no CHECK)
message       TEXT NOT NULL        -- frozen at write time; the record
created_at    TEXT NOT NULL DEFAULT (datetime('now'))
Index: (task_id, created_at, id) · backfill: one created row per existing task (from tasks.created_at) · never pruned (contrast: webhook_events 7-day)
XSS rule: message and labels contain user-controlled strings (column names, actor names) frozen at write time — frontend renders them as plain text, never HTML. Mention highlighting applies only to TipTap comment bodies.

02Actor model — resolved at the boundary

Services receive actor: Actor {kind, label, userId?} as a parameter — transport-agnostic. Attribution ≠ authorization: a bound key authorizes with the owner's permissions but is attributed as the agent ("opencode-local moved…", never "Maria moved…"); actor_user_id records whose key drove it.

03Services — emission discipline, no cycles

LAYERS.md additions. ActivityService is a leaf — never depends on TaskService (preserves invariant #1).

Routes REST route handlers · MCP handlers · Webhook handler
Services TaskService — create · update · move · archive · restore · delete · links · sources · github
ForgeService — terminal state + accept/reject CommentService — create · edit · delete + authz
Leaf ActivityService — append() · listMerged() no dep on TaskService
DB task_activity · task_comments
New invariant: every task mutation emits exactly one task_activity row in the same transaction as the mutation (batch()). Emission inside services — the webhook bypassGuards move path is covered automatically.

04API surface — REST + MCP

API.md + MCP.md additions. Exact shapes.

GET/api/projects/:slug/tasks/:id/activity?cursor&limit
→ 200 { data: ActivityItem[], nextCursor }  Item = {kind:'event', id, type, actorKind, actorLabel, message, createdAt} | {kind:'comment', id, authorKind, authorLabel, body: TipTapDoc, editedAt, createdAt}
POST/api/projects/:slug/tasks/:id/comments body { body: TipTapDoc }
→ 201 { data: { comment, activity } } · activity = the 'commented' row
PATCH/api/projects/:slug/tasks/:id/comments/:commentId body { body } · author only
→ 200 { data: Comment } · sets edited_at, marker only — no activity row (avoids noise)
DELETE/api/projects/:slug/tasks/:id/comments/:commentId author or project admin
→ 204 · soft delete + 'comment_deleted' row

Response envelope rule (invariant #6): all task mutations return the appended activity row(s) via activity?: ActivityEvent[]. Client prepends with setQueryData — never invalidateQueries on the mutation path. Webhook-driven entries appear on next slideover open (documented).
