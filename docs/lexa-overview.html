Lexa.

Self-hosted project management for small game-dev teams (2–5 people). A kanban board, a nested wiki, an AI writing assistant, an MCP server for agents, and two-way GitHub issue sync — one Bun process, one SQLite file, one docker compose deploy behind a cloudflared tunnel.

Bun SQLite (WAL) TanStack Start React Effect-TS Tailwind cloudflared MCP server lexa-cli

Humans: Cloudflare Access (no passwords) · Machines: lxk_ Bearer API keys · Agents: 35 MCP tools · AI writing: Forge (opencode · hermes · command-code) · Sync: GitHub App + webhooks, echo-suppressed

Reading path: What it is → Architecture → Data model → Auth → Agent surfaces → GitHub sync. Deep-dive links in the docs index.

01

What it is

One product, six surfaces

Lexa is a single self-contained Bun server that does SSR, REST, MCP and webhooks. The frontend (TanStack Start + React) renders the board and wiki; the same Effect-TS services back every surface. Comments and email notifications were cut by design — for a 2–5 person team, breakdown lives in the task description, and GitHub owns issue discussion.

Kanban board

Columns with swimlanes (horizontal grouping), WIP limits enforced atomically inside the move statement, required-field gates, drag-and-drop with stable fractional-index ordering, task archive/restore, per-project priority and type labels, and task links: subtasks, blocked-by, related-to.

WIP limitrequired_fieldsfractional-indexsubtask_of

Nested wiki

Nested pages with a collapsible tree, rich-text TipTap editing, full-text search backed by SQLite FTS5, and revisions with restore (autosave + manual buckets). The same editor is used for tasks and wiki; content converts Markdown ↔ rich text at the MCP boundary.

FTS5revisionsTipTap

Forge — AI writing assistant

A Forge button in the task/wiki editors. Pick an agent (rule bundle) + a skill (operation bundle), and an online runtime daemon runs an agent CLI (opencode / hermes / command-code) on your selection with project context, streams a live activity log, and returns a result to accept or reject.

agentsskillsruntimes

MCP server for agents

Streamable HTTP at /mcp — 35 tools for managing projects, tasks, wiki and GitHub links. Agents pass names, not UUIDs (columns by name, projects by slug) and speak Markdown, never ProseMirror JSON. Remote agent clients use the same lxk_ keys as everything else.

35 toolsnames, not UUIDsMarkdown

Two-way GitHub sync

A GitHub App (Issues r/w + Metadata read only) links tasks to issues. Move a task to a state-mapped column → its issues close/open on GitHub. Close or reopen an issue → the task follows, echo-suppressed and deduplicated so nothing loops.

echo suppressionwebhookcolumns.github_state

lexa-cli — operator CLI

For humans and operators, not agents. Manages the Forge machine listener (machine install|listen|start|stop|restart|status|logs|list), CRUD for tasks/wiki/projects, and deployment: lexa-cli deploy <domain> dev|staging|prod (Docker + cloudflared tunnel + Access).

machine listenerdeployCRUD
Deployment posture: one Bun process serves SSR + REST + MCP + webhooks on :3000; the DB is a local SQLite file (data/lexa.db, WAL mode). Production runs behind a cloudflared tunnel with Cloudflare Access in front for humans. Dev runs the API on :3000 and Vite on :5173, which proxies /api and /mcp to the server.
02

Architecture

One process, layered services, no cycles

Everything runs inside one Bun process: the HTTP edge (server/entry.ts), the @effect/platform HttpApi router with its middleware stack, Effect-TS services, thin SQLite repositories, the MCP server, and the GitHub webhook branch. The strict layer rule: routes orchestrate, services never call each other in both directions — TaskService has no GitHub dependency; Lexa→GitHub sync happens in the route layer after a successful move.

  1. Edge — Browser/humans via Cloudflare Access (JWT verified when LXK_ACCESS_AUD set); agents via /mcp; GitHub via webhooks (HMAC); Forge machines via the listener.
  2. server/entry.ts — boot + migrations · stream cap (readBodyWithLimit) · socket IP stamp (x-lexa-remote-ip, spoof-safe) · webhook branch · /mcp · SSR/static · body cap → 413.
  3. API middleware — 1. rate limit (600/10min, shared w/ /mcp) · 2. content-length pre-check → 413 · 3. auth (daemon token / Bearer / exempt) · 4. AuthIdentity provision · 5. security headers (nosniff + no-store).
  4. Forge endpoints — /api/forge/*: runtime-events (wizard → listener) · machines (register/heartbeat) · daemon/* · tasks.
  5. Effect services — Task · Wiki · Project · Column · Swimlane · FieldConfig · TaskLink · Dashboard · Auth · GitHub · Forge · Source.
  6. Repositories — thin, raw SQL: RowNotFound | DbError | ConstraintViolation.
  7. SQLite — data/lexa.db (WAL) · one connection · FK pragmas on · batch() transactions.
Lexa deployment topologydev: vite :5173 → proxy /api + /mcp · prod: built dist/ served on :3000

Frontend

TanStack Start + React: SSR for the initial load, SPA-like afterwards, file-based routing. Tailwind for styling, TipTap for rich text, @dnd-kit for drag-and-drop. Mutation responses are authoritative — the cache updates via setQueryData, never a refetch on the mutation path.

03

Request pipeline

entry edge + HttpApi middleware, in order

Requests enter through server/entry.ts, the Bun.serve edge: boot/migrations, the webhook branch (HMAC before any parsing), /mcp (rate check + stream cap + handler), static/SSR, and the /api stream cap — chunked bodies cannot bypass LXK_MAX_BODY_MB. The resolved socket IP is stamped as x-lexa-remote-ip (any inbound value deleted first — spoof guard), because remoteAddress is unpopulated on the web-handler path.

  1. Normal path — Client → entry.ts (stream cap 16 MB · IP stamp x-lexa-remote-ip) → 1. rate limit (600 req / 10 min · per IP) → 2. content-length pre-check (declared > 16 MB → 413) → 3. auth (Bearer key / exempt) → 4. AuthIdentity (provided, not re-fetched) → handler → 5. security headers (nosniff + no-store) → Client.
  2. Webhook path (GitHub → Lexa, no API key) — POST /api/webhooks/github (X-Hub-Signature-256) → HMAC verify (raw body, before parsing) → Ack 200 (respects GitHub 10s timeout) → background (waitUntil-style): dedup · echo check · atomic move → record delivery only after success.
Middleware order is fixed: rate limit → content-length → auth → AuthIdentity → handler → security headersliteral short-circuits only (no undeclared Effect.fail — 500 trap)

Rate limiting

Fixed window, per client IP: 600 requests / 10 min (defaults in server/api/rate-limit.ts). Enforced before auth — a blocked IP stays blocked regardless of key. One shared bucket (apiRateLimiter) covers /api/* and /mcp. Denied → 429 RATE_LIMITED with Retry-After. Client IP: socket address, with CF-Connecting-IP trusted only when the socket peer is private (tunnel sidecar).

before authshared bucketRetry-After

Exemptions, deliberately

/api/setup/* and /api/health stay rate-limited (unauth surfaces keep their throttle) but skip auth. /api/forge/daemon/* + /api/forge/runtimes/register are rate-limit-exempt and accept the daemon token (x-forge-token) — log streams must not 429. The webhook is exempt too: HMAC-authenticated, and GitHub delivers in bursts.

setup + health limiteddaemon token-gatedwebhook exempt

Body caps

LXK_MAX_BODY_MB defaults to 16 MB for /api and /mcp: a stream cap in entry.ts (authoritative — chunked/CL-less bodies included) plus a declared-length pre-check in the middleware (fast path). Oversized → 413 BODY_TOO_LARGE. The webhook route is stream-capped at 1 MB (entry.ts) on the trusted, HMAC-gated channel — large pushes (many commits) can exceed it and 413, which GitHub retries.

stream cap413 BODY_TOO_LARGE

Platform quirks that shaped this

MaxBodySize is unenforced in @effect/platform 0.97 (the stream cap must stay in entry). remoteAddress is unpopulated on the web-handler path (hence the IP stamp). Middleware must short-circuit with literal HttpServerResponse values — failing with undeclared errors hits the error encoder and 500s. Router 404s carry the security headers via RouteNotFound.

HttpServerResponse literalsRouteNotFound

Data model highlights

SQLite, one schema — full DDL in docs/SCHEMA.md

TEXT UUIDs (crypto.randomUUID()), local WAL file, FTS5 for wiki search, one clean migration (migrations/0001_init.sql). Board fetches ride one index: idx_tasks_board (project_id, column_id, position). The 12 architectural invariants below are the hard-won rules that keep the board, the sync loop and the agent boundary honest.

projects

slug UNIQUE (duplicate → 409 SlugTaken), github_repo = "owner/repo" for the GitHub link. Cascades: columns, swimlanes, tasks, wiki.

slug UNIQUEgithub_repo

columns

wip_limit (NULL = none), required_fields JSON array (the only column policy), github_state open/closed (explicit sync mapping — exactly one column per project should map to closed), position INTEGER (ties harmless), color.

wip_limitrequired_fieldsgithub_state

swimlanes

Horizontal groups; every task belongs to one (NOT NULL). New projects get a default "Default" swimlane. Deleting a lane with tasks is rejected — reassign first.

NOT NULL on tasksDefault lane

tasks

position = fractional-index key, UNIQUE(column_id, position). description is TipTap JSON. archived_at soft-archive keeps column/position; excluded from board/WIP/count unless includeArchived. priority/type are label strings validated against per-project options.

fractional-indexTipTap JSONarchived_at

task_links

One directed table for subtask_of / blocked_by / related_to. Subtask children inherit the parent's column; moving a parent cascades (WIP-bypassed); cycles rejected (TASK_LINK_CYCLE); deleting a parent with children blocked.

subtask_ofblocked_byrelated_to

wiki_pages + revisions

Nested via parent_id (ON DELETE RESTRICT — no silent re-rooting), content TipTap JSON, content_text plain-text projection backing an FTS5 external-content table (wiki_fts + triggers). Revisions split into autosave / manual buckets, restorable.

FTS5ON DELETE RESTRICTrevisions

priority_options / type_options

Per-project ordered option lists — labels, colors, positions. The FIRST option (position 0) is the create default and the dashboard "urgent" equivalent. Delete is blocked while any task uses the option (OptionInUse).

position 0 = defaultOptionInUse

api_keys

Raw format lxk_ + base62(32 random bytes); stored as unsalted key_hash = hex(SHA-256), UNIQUE (also the lookup index). user_id NULL = unbound → admin; linked keys inherit the user's role and project grants. last_used_at sampled (only when NULL or >1h old).

SHA-256 hashadmin when unlinked

task_github_issues

Junction: one task ↔ many issues, one per repo. PK (task_id, issue_id) + UNIQUE(issue_id) (issue → at most one task). Per-link synced_state is the echo-suppression memory. repo captured at link time, never parsed from URLs.

per-repo ALREADY_LINKEDsynced_state

settings + webhook_events

settings is a key/value store (e.g. admin_emails, mirrored from LXK_ADMIN_EMAILS). webhook_events dedups GitHub at-least-once deliveries on X-GitHub-Delivery — INSERT happens only after successful processing; rows pruned after 7 days.

dedup7-day prune

machines + runtimes

machines: secret minted once at register, required on event claims (x-machine-secret); ids are hostname-<unique>; heartbeat every 3s; offline after 2 min. runtimes: one daemon per provider per machine, server-authoritative config (model, extra_args, log_level), daemon-reported models_catalog / agents_catalog (refresh at boot + ~10 min).

x-machine-secret3s heartbeatcatalogs

forge_tasks + agents + skills

forge_tasks: queued → running → completed/failed/cancelled, FIFO conditional claim (WHERE status='queued'). forge_agents / forge_skills: global rule bundles (M2M); "Lexa" default agent + five builtin skills (continue · rewrite · summarize · expand · grammar) — builtins editable + resettable, never deletable. document_sources ground output (wiki slug or external URL, SSRF-guarded). forge_task_logs: append-only live activity feed.

rule bundlesFIFO claimSSRF guard
The 12 architectural invariants — non-negotiable, never break these
01No service-to-service cyclesTaskService must never depend on GitHubService. Lexa→GitHub sync is orchestrated by route handlers only.
02Echo suppressionEvery Lexa→GitHub state sync writes github_synced_state; the webhook skips payloads matching it. Delivery is recorded after successful processing, never before.
03Webhook moves bypass guardsbypassGuards: true, one atomic transaction (move + synced-state write). Webhook acks 200 immediately, processes in waitUntil.
04Fractional-index positionsGeneration is deterministic — retries re-read anchors before regenerating. Neighborless moves append to end; never generateKeyBetween(null, null) into a non-empty column. Retry only on isPositionConflict, at most once.
05WIP limit is atomicEnforced inside the conditional UPDATE, with the within-column-reorder short-circuit (column_id = ?2 OR count < limit).
06Mutation responses are authoritativeFrontend updates the TanStack Query cache via setQueryData from the mutation response. Never invalidateQueries on the mutation path.
07MCP speaks Markdown; REST speaks TipTap JSONConversion lives only in shared/markdown.ts and server/mcp/. Agents never see ProseMirror JSON; the frontend never sees Markdown.
08MCP takes names, not UUIDsColumns/swimlanes by name, projects by slug. Failed lookups return details.available* with valid choices.
09Webhook has no API-key middlewareHMAC-SHA-256 signature verification over the raw body is the auth, and it runs before JSON parsing.
10Column→GitHub state mappingUses columns.github_state, never column names — renaming "Done" can't break sync.
11required_fields everywhereEnforced on create, move, AND update, with TipTap-aware emptiness (a doc with no text nodes is empty).
12Issue ↔ task cardinalityAn issue links to at most one task; a task may hold several issues, one per repo (task_github_issues PK + UNIQUE(issue_id) + per-repo ALREADY_LINKED guard).

Auth model

four principals, four credentials

Lexa authenticates four different callers with four different credentials. No sessions, no cookies, no CSRF surface, no auth routes — the browser path terminates at Cloudflare Access at the edge, and every machine path carries its own secret.

PrincipalCredentialWhere enforcedNotes
Humans (browser) Cloudflare Access JWT / identity header Edge (Access policy), optionally verified server-side Email allowlist or GitHub org policy in the CF dashboard. Server reads Cf-Access-Authenticated-User-Email for identity. With LXK_ACCESS_AUD set, Cf-Access-Jwt-Assertion is verified against the team JWKS (SSRF-hardened fetch) and users are upserted from the claims; without it, headers are trusted as-is (tunnel-authenticated, boot warning).
Machines / agents Bearer lxk_<base62(43)> API key /api/* + /mcp middleware Key format ^lxk_[0-9A-Za-z]{43}$; SHA-256-hashed lookup in api_keys. Unlinked key (no user_id) = admin; user-linked key inherits the user's role and per-project grants. Admin-only gate (requireAdmin → 403 FORBIDDEN) on project/column/swimlane mutations, API-key and admin routes, Forge agent/skill CRUD.
GitHub webhook HMAC-SHA-256 (X-Hub-Signature-256) Webhook route, before body parsing No API key on this route by design. Constant-time comparison over the raw body; failure → 401 GITHUB_WEBHOOK_ERROR, no processing. Rate-limit-exempt (burst delivery), HMAC-gated.
Forge daemon x-forge-token (LXK_FORGE_DAEMON_TOKEN) or Bearer key /api/forge/daemon/* + /api/forge/runtimes/register Constant-time token compare; rate-limit-exempt so log streams never 429. A revoked runtime key makes daemon calls 401 — the daemon exits with code 3 and the listener relays last_error.
Machine listener Bearer key + per-machine x-machine-secret /api/forge/runtime-events/claim The secret is minted once at register, returned a single time, persisted at ~/.lexa/machine-secret (chmod 600), required on every claim. Mismatch → 403 identical for missing machine / legacy / wrong secret — no existence oracle.

Security posture

Rate limit 600/10 min per IP before auth · body cap 16 MB streamed · nosniff + no-store on every API/MCP response (and the key-bearing SSR HTML) · SSRF guard on external Forge sources and the JWKS fetch (DNS resolve → reject private/loopback/link-local/CGNAT) · constant-time HMAC · no raw error internals (codes only).

defense in depthno-storeSSRF guard

Keys & identity

The server injects its current key into served HTML (<meta name="lxk-api-key">); the client prefers it over any build-time key, so rotation never breaks the browser. last_used_at is sampled (max one write per hour per key). Setup wizard endpoints lock with 403 SETUP_LOCKED once configured.

rotation-safeSETUP_LOCKED

Error envelope

Every non-2xx response shares one shape: {"error": {"code", "message", "details"}}. Tagged errors map declaratively to statuses (404/409/422/429/502…) via the HttpApi error catalog — no hand-rolled per-route mapping to drift.

declarative mappingcodes, not internals

Forge — the AI writing assistant flow

Web wizard → runtime events → listener claims → sandboxed agent run → streamed result back to the editor. Every host-side artifact lives under ~/.lexa/ (LEXA_DIR override); the listener migrates legacy ~/.config/lexa-* dirs (migrate-and-delete).

  1. 1 · Web wizard — Settings → Setup runtime: lists machines, picks agent CLI, sends machine + agent CLI + fresh key via POST /api/forge/runtime-events.
  2. 2 · Listener claims — lexa-cli machine listen claims with x-machine-secret; heartbeat 3s; ~/.lexa/ holds machine-id + machine-secret (chmod 600).
  3. 3 · Daemon child — one per runtime; runtimes/<id>/env (chmod 600); registers as runtimes row; polls forge_tasks (FIFO).
  4. 4 · Sandboxed run (opencode) — cwd = ~/.lexa/projects/<id>/; sealed per-run HOME at .forge/ (wiped); AGENTS.md + .agents/<skill>/SKILL.md; deny: bash · external_directory · skill · webfetch.
  5. 5 · Stream + report — forge_task_logs (append-only); complete → result · fail → error; UI polls while queued/running.
  6. 6 · Editor — Accept / Reject; result replaces selection; closing popup never cancels. Trigger: Forge button in editor (agent + skill + extra prompt → POST /api/forge/tasks; NO_RUNTIME_ONLINE if no daemon up).
  7. Containment (opencode only): bash denied (not path-scoped) · external_directory denied on resolved paths · skill/webfetch denied · *auth.json* denied (copied auth.json instead) · global config never loads · PWD must be the workspace · .forge/ wiped after each run.

GitHub sync

state flows both ways, text flows one way, nothing loops

A GitHub App (Issues: Read & Write, Metadata: Read — nothing else) subscribes to issues.closed / issues.reopened / issues.edited. Installation tokens are cached ~50 min, never minted per call. The asymmetry is deliberate: Lexa owns the board, GitHub owns the issue text — so only state flows both ways, and the conflict surface stays minimal.

  1. Lexa → GitHub — Move task in Lexa → taskService.move() → githubService.syncStateFromLexa() (best-effort).
  2. GitHub → Lexa — Issue closes / opens (per stored link, repo captured at link time) → webhook → POST /api/webhooks/github → HMAC verified · delivery dedup (webhook_events) · ack 200 → background.
  3. Echo check — payload.state == synced_state? → YES = echo, skip no move · NO = move task (bypassGuards: true, atomic).
  4. Guards — Column lookup by github_state, never by name · record delivery after success · issues.edited → title: GitHub wins, body/assignees never sync.
Echo-suppressed, deduplicated, idempotentmove() early-returns on no-op · archived tasks are never moved
DataLexa → GitHubGitHub → LexaNotes
Issue state ↔ column ✓ ✓ Lexa→GitHub on task move via columns.github_state (best-effort, non-blocking — a GitHub failure never fails the move). GitHub→Lexa on webhook, bypassing WIP and required-fields guards.
Issue title ✗ ✓ GitHub wins on issues.edited.
Issue body ↔ task description ✗ ✗ Link only — text stays in its home system.
Assignees ✗ ✗ Not synced.

Loop-killers, in order

1. webhook_events dedups on X-GitHub-Delivery (at-least-once). 2. Webhook acks 200 immediately, processing in the background (GitHub's 10s timeout). 3. Echo suppression: per-link synced_state comparison — our own push is skipped. 4. Column lookup by github_state, never by name. 5. Webhook moves bypass WIP + required fields (bypassGuards: true), one atomic transaction.

dedupecho skipatomic move

Divergence is surfaced, not hidden

Failed Lexa→GitHub sync diverges by design — best-effort, no retry queue. The UI shows it: a linked task displays "out of sync" when synced_state ≠ its column's github_state (amber dot on the card, listed in the dashboard attention section). A manual re-move resyncs.

outOfSyncre-move resyncs
Trust boundary (explicit decision): anyone with issue-triage permission on a linked repo can trigger webhook-driven board moves (close/reopen an issue → the card moves, bypassing WIP and required_fields). This is intentional — GitHub is the source of truth for issue state. On public repos, external contributors can affect the board; the mitigation is restricting the App to private repos or filtering webhook senders — not more auth code.
