03Data flow — board payload, one cache

No backend change. useTasks() wraps the board query under the same key, so board and list share one fetch and one cache entry.

Server
① GET /api/projects/:slug/board · unchanged · full snapshot: columns, swimlanes, fieldConfig, links, tasks (columnId, position)
Client cache
② react-query key ["board", slug, showArchived] · shared: useBoard (kanban) + useTasks (list) — one fetch
New hook
③ useTasks(slug, showArchived) · derives flat list: columnName, swimlaneName, priority/type label + color from fieldConfig
Consumers
④ /$slug/tasks — search, column/type/priority filters, archived toggle, sort · all in-memory useMemo · filters live in component state (survive detail close)
⑤ ?task=<id> → TaskDetail slideover · same component + param pattern as the board · mutations update cache via setQueryData (invariant 6)

05Edge cases

Explicit behavior decisions — no crash paths.

ScenarioBehavior
No project / stale selectedSlugSame redirect + needsSetup behavior as board (getSetupStatus); provider fallback chain
Empty project (no tasks)Empty state with CTA to board
Filters active, no matches"No tasks match" + clear-filters button — never the empty-project state
Archived toggleBoard semantics: archived excluded from counts; toggle shows dimmed archived rows
Task deleted/archived while detail openExisting TaskNotFoundDialog (same as board)
Detail close / backClears ?task=, returns to the filtered list — filters in component state, not URL
Mutations from detail slideoversetQueryData on the shared board key refreshes the list; never invalidateQueries (invariant 6)
Board query errorError panel + retry; never empty state on error
Dropdowns with missing valuesOnly values present in the project are listed (columns / fieldConfig)
