Milestone Deadlines · Backlog Lane · Lane Archive

Proposed Lexa board feature: swimlanes become milestones with optional due dates, a system Backlog lane catches unassigned tasks, and milestone lanes can be archived. Decisions locked 2026-08-09. This artifact mirrors the real PHOSPHOR board vocabulary (tokens + kanban classes) so the look is the true app look.

01Overview — locked decisions

Swimlanes = milestones. One system Backlog lane. Deadlines live on lane headers; cards may add their own (bounded by the lane date).

Swimlane model: every swimlane gets an optional due_at (YYYY-MM-DD, date-only, no time-of-day). A lane without a due date is allowed and renders no chip. Backlog = system lane: created automatically, cannot be renamed/archived/deleted, has no deadline field. Every task without a swimlane lands here. Identity is kind, not name — the label is always "Backlog". Countdowns: "N d left" for future deadlines, "Overdue Nd" (red) once past. Countdown computed client-side from due_at; the stored value is the date only. Archive: only milestone lanes archive. Archiving archives the lane's live tasks in one transaction; restore brings the lane back only — tasks restore individually.

05Move dialog states

Both dialogs render as the standard popover/menu treatment. Two distinct warnings exist.

Overdue lane
Lane v1.0 is overdue (2d). Move anyway?
State (a) — move into overdue lane: confirm dialog before the move lands. Move proceeds as a normal atomic move (position + synced-state write); no guard changes — the warning is informational, overdue is not blocking.
Deadline conflict
Card is due Fri; lane Demo 2 is due Wed. Card deadline is after the lane deadline.
Clear card deadline (Fri → none)
State (b) — card deadline conflict: checked "Clear card deadline (Fri → none)" sends clearDueAt in the same atomic move. Without the flag the server rejects with 409 DEADLINE_AFTER_LANE.
