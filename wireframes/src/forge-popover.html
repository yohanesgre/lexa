Opens from the Forge toolbar button in task detail + wiki editors. Agent: a named rule bundle defined in Settings — its instructions become AGENTS.md in the run dir. NOT the runtime's CLI agent (that's the "CLI"/"Persona" on the runtime row). Builtin "Lexa" is the default; the list is editable + extensible in Settings. Skill: a named operation bundle attached to agents (M2M). Chips show only the selected agent's attached skills; changing the agent resets the skill to its first attached. Builtins: Requirements · Deliverables · Review · Definition of done · Status · Polish. Overflow: more than 6 agents or skills collapses the row into a dropdown (chips stay for the first 6). Empty-skills state: an agent with zero attached skills shows the hint + disabled Generate — skills must be attached in Settings first. Additional prompt: per-run free text appended to the prompt (stored on the task, cleared on popover close). Optional. Rules delivery: the server embeds the chosen agent + skill rules into the claim response (agentMarkdown/skillMarkdown); the daemon writes them into the run dir as AGENTS.md + .agents/<skill>/SKILL.md. No host-side store — edits apply to the very next run. Runtime: pick which daemon runs the request (any online runtime — no Lexa MCP connection required; Settings shows the MCP state per runtime as informational). Forge uses the current task/wiki page as context. Generate → POST /api/forge/tasks → daemon runs agent CLI → result → Review in editor (forge-review.html) / Reject. While a result is being reviewed in the editor, this popover shows "In review in editor" and hides its buttons. After Accept in the review banner (forge-review.html), the task is marked applied and the popover starts fresh — the next open lands on Generate, never on the applied result (it can't be inserted twice). Reject (popover or banner) keeps the task reviewable — the result can be inserted again from the popover if you change your mind. Rejected tasks are not re-attached on reopen this session. Background: closing the popup does NOT cancel a running task — it completes server-side and re-appears here next open. Overflow: the popover anchors 6px below the Forge button, but when it would extend past the bottom of the viewport it flips above the button (8px gap); left edge is clamped to the viewport. Every control stays reachable — the popover never clips off-screen buttons (the Review in editor / Reject row must never fall below the fold). The popover shows the target document name (task title / wiki page title), never the raw result body — the result text appears only in the editor review.
